# Resume bullets

Each number below comes from a committed, script-generated result; the source is linked under the
bullets. x86 numbers are from an AWS c7i.8xlarge (single thread unless stated); *M2* marks Mac
development results.

## Short version (3 bullets)

- Built **Strata**, a vector search engine in C++20 from scratch: HNSW (Malkov & Yashunin, 2018),
  AVX2/NEON SIMD kernels, product quantization, filtered search, a crash-safe write-ahead log, and
  gRPC sharding with TLS, plus a Python RAG layer with cited answers.
- Matched hnswlib's recall at every setting on SIFT1M, GloVe-100, and BIGANN-10M. At equal SIMD
  width on x86, came within 6–7% of hnswlib's queries per second, was fastest of the three on
  GloVe-100, ran 15–77% faster than FAISS HNSW, and built SIFT1M fastest (333 s vs 364 s and
  493 s).
- Scaled index builds 15.3x and search 14.4x on 16 cores. `perf` profiling showed search is
  memory-latency bound (~0.55 IPC), which explains why AVX-512 gave the reference libraries at
  most 6%.

## Longer version (pick and choose)

- **Core search.** Implemented HNSW with the paper's neighbor-selection heuristic, software
  prefetching (about 2x on 200k vectors, *M2*), tombstone deletes, and versioned snapshots that
  load in 0.39 s instead of a 25.6 s rebuild (*M2*).
- **Benchmarked against hnswlib and FAISS** with ann-benchmarks methodology (recall@10 vs QPS
  curves, 5 runs per point), like for like at 256-bit SIMD with each library's instruction set
  verified at run time. Strata was within 6–7% of hnswlib on SIFT1M and BIGANN-10M, fastest on
  GloVe-100 (5,040 QPS at recall 0.79), and 15–77% faster than FAISS.
- **Cross-platform.** The same code on ARM (Oracle Cloud A1, NEON kernels): about 10% faster than
  FAISS at equal SIMD width on SIFT1M (4,455 vs 4,034 QPS, same recall), fastest build, and 3.4x
  search scaling on 4 cores. All tests pass under ASan, UBSan, and TSan on macOS ARM, Linux ARM,
  and Linux x86, with zero GCC and Clang warnings.
- **Parallelism.** Parallel graph construction with a striped lock table: 322 s → 21 s on 16
  threads (15.3x) with identical recall and graph statistics. Search throughput 14.4x on 16 cores
  (90% efficiency).
- **Profiling.** `perf` on x86: graph traversal 54% of cycles, the AVX2 distance kernel 33%,
  ~0.55 instructions per cycle. Search waits on memory, not arithmetic.
- **Filtered search** with automatic strategy selection between an exact pre-filter and filtered
  graph traversal. The switch-over threshold is fitted to crossovers measured at 1M and 10M
  vectors (1.48% and 0.89%), with a cost-budgeted fallback that preserves recall.
- **Durability.** A write-ahead log with CRC32C and LSN-ordered replay. Kill-mid-write crash tests
  lose no acknowledged write.
- **Distributed serving.** A gRPC shard server and coordinator with async fan-out (+17–23%
  throughput over thread-per-shard, *M2*), idempotent batch retries after partial failures, TLS
  and token auth. On a 4-machine AWS cluster: 1M vectors ingested 4.8x faster than on one shard,
  p99 latency 1.4 ms at half load.
- **Retrieval-augmented generation.** BM25 that reproduces Anserini exactly (SciFact nDCG@10
  0.6789); hybrid BM25 + dense with reciprocal rank fusion reaches nDCG@10 0.730 on the full
  5.2M-passage HotpotQA corpus; multi-hop reranking lifts answer F1 from 0.517 to 0.669 (gold
  passages: 0.739).
- **Reproducible cloud benchmarking.** Ran the x86 session on AWS with Terraform, a least-privilege
  IAM policy checked with EC2 dry runs, and verified teardown, for about $30 total. Every number
  is generated by a script that records commit, hardware, and parameters.
